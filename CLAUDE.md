# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

PoB2's own calc engine in the browser: Path of Building 2's Lua (unmodified, pinned at `vendor/pob2`, a submodule of a fork at a **release tag**, not `dev`) running on PUC Lua 5.2.4 patched and compiled to WebAssembly. Static hosting on GitHub Pages, no server. `README.md` is detailed and authoritative (numbers, API, autoConfig rules, bump procedure); `docs/PORTING.md` logs every PUC-vs-LuaJIT incompatibility found.

## Commands

Setup (Node >= 22, gcc, emsdk 4.0.10 for wasm):

```sh
scripts/checkout-pob2.sh --specs   # sparse checkout of the pinned PoB2 commit + spec/ (~40 MB; full `git submodule update --init` is ~400 MB)
npm ci
source "$(scripts/install-emsdk.sh 4.0.10)"   # only for the wasm build
native/build.sh all                # build/native/pobcalc (native CLI/host) + dist/engine.{mjs,wasm}   (npm run build = this + pack)
node scripts/pack.mjs              # dist/ packs + manifest; compile-checks every bundled Lua file (--bytecode for bytecode packs)
```

Tests (CI order is in `.github/workflows/pages.yml`; the native build must exist first for anything that runs Lua):

```sh
npm run test:model | test:edit     # decoder/model/edit: pure JS, no engine needed
node --test test/data-fresh.test.mjs test/affix-tiers.test.mjs test/modrange.test.mjs test/gem-data.test.mjs   # pure JS
build/native/pobcalc test/lua/compound_spec.lua   # patch spec (npm run test:spec)
scripts/pob-specs.sh [spec files]  # PoB2's own spec suite on the native host, one process per file (~70 s)
node --test test/parity.test.mjs   # wasm vs LuaJIT oracle, snapshot + every group (~30 s)
npm run test:parity:dist           # same against the shipped packs
npm run test:corpus                # corpus-parity + rule-matrix (native engine, ~15 s PoB boot per fixture)
node --test test/autoconfig.test.mjs
node --test test/e2e.test.mjs      # Chromium via Playwright
node --test --test-name-pattern='<regex>' test/<file>   # single test
npm run serve                      # dist/ at http://127.0.0.1:8080/
```

Debug PoB itself natively: `build/native/pobcalc lua/cli.lua <build.xml|code.txt> [--groups] [--auto-config[=suggest]] [--set=key=value]`.

## Architecture

Layers, bottom to top:

- **`third_party/` + `native/`**: pristine Lua 5.2.4, LuaBitOp, luautf8, zlib; `native/patches/` (4 patches, applied by `native/build.sh`) make 5.2 behave like PoB's LuaJIT (compound assignment, `gsub` replacement rules, `%d` truncation, `_ENV` as a plain name). `native/pobcalc.c` is the host (provides global `bit`, `lua-utf8`, `pobhost` for zlib/chdir/clock) and builds both natively and with emcc (`pob_boot`/`pob_eval` exports). Any new LuaJIT-vs-PUC difference becomes a documented patch/shim, never an edit to `vendor/pob2`.
- **`lua/`**: the shim that boots PoB headless (`headless.lua`, `groups_lib.lua`, ported from the companion repo's `tools/pob2`), `calc.lua` (per-build logic, the `CALC.*` functions JS calls), `autoconfig.lua` (opt-in Config inference + catalog/leave-one-out measurement), `cli.lua` (native entry), `spec_runner.lua` (busted-compatible runner).
- **`web/engine-core.mjs`**: `wrapEngine(Module)` — the only JS<->Lua bridge. Requests go in as JSON via the Emscripten FS (`/tmp/request.json`, decoded with dkjson in Lua), not as C string args. Shared by the browser worker (`web/pob-worker.js`) and Node tests (`test/node-engine.mjs`, which mounts `vendor/pob2` and `lua/` straight from the repo via NODEFS, so Lua edits need no repack for parity tests).
- **`web/pob-calc.js` + `pob-worker.js`**: public API (`init`, `calc`), calls serialised in one module worker; Cache Storage keyed by content hash; lazy per-version passive tree. `scripts/pack.mjs` writes `dist/` (gzipped `PCK1` packs from `web/pack.mjs`, `manifest.json`).
- **Pure-JS build tooling (no engine)**: `decode.mjs`/`encode.mjs` (PoB code <-> XML), `xml-lite.mjs`, `build-model.mjs` (typed model, keeps XML ids for round-trip), `build-edit.mjs` (`editBuild`), `affix-tiers.mjs`/`affix-data.mjs`, `gem-data.mjs`. Data in `web/data/*.json` is generated by `npm run extract` from `vendor/pob2` and stamped with `source.pob2Commit`; `test/data-fresh.test.mjs` fails when it doesn't match the pin.

## Fixtures and parity

- `fixtures/oracle/ninja-default.*` are copied byte-for-byte from the companion repo (`upgraded-disco-companion`) and never hand-edited; regenerate there after a PoB bump. Parity target: 1e-9 relative, TotalDPS 186,706.45.
- `fixtures/corpus/` is produced by `node scripts/make-corpus.mjs`. Only `ninja-default` and `monk-unconfigured` are real exports; **all other fixtures are synthetic** (ninja-default XML edited, oracle = our own native recompute), so they catch regressions, not engine errors.

## Gotchas

- Pin = PoB2 release tag commit; `dev` gives different numbers. Bump procedure is in README "Bump PoB2" and must stay in lockstep with `upgraded-disco-companion` (`vendor/pob2` and `apps/web/pob-calc.lock.json`). Release tags are `vX.Y.Z-N`.
- Affix tier lookup trusts the item's recorded level: tiers above item level are reported (`exact-above-ilvl`), never silently filtered.
- `vendor/pob2` is never edited. Build outputs (`build/`, `dist/`) and test reports are gitignored.
- Only `main` deploys to Pages; PRs run the full build/test job without deploying.
